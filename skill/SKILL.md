# むしとり記録(bug-visits)

以前は場所マスタ(`bug-spots`)と記録(`bug-visits`)の2コレクションに分けていたが、ユーザーの希望で**1つに統合**した。場所の名前・種類・緯度経度は各訪問記録に直接持たせる(参照はしない)。同じ場所に何度も行くと、そのつど同じ緯度経度が重複して保存される — これは意図した簡素化であり、正しい挙動。場所の座標を後から直す場合は、該当する複数レコードすべてを更新する必要がある点に注意。「地図」ビューは同じ場所名+座標のレコードを自動でグルーピングして1本のピンにまとめ、訪問回数を数えて表示する。

## ワンライン登録(最優先の使い方)

ユーザーはできるだけ手間をかけたくないので、フォームや確認質問を挟まず、**一言のチャットメッセージだけで登録を完結させる**のが基本方針。例:「日向神社でセミ2匹とバッタ1匹とった」「今日は雨で〇〇公園、カマキリ1匹だけ」。

このようなメッセージを受け取ったら、次の手順で処理し、完了したら1〜2行の確認メッセージだけ返す(`presentForm` や `presentCollection` は基本呼ばない。ユーザーが明示的に「見せて」と言った時だけ表示する)。**唯一の例外**は、生き物の種名が下記「総称語は1回だけ質問する」の一覧に該当する曖昧な総称で、かつ具体的な種名がメッセージに書かれていない場合 — そのときだけレコード保存前に `presentForm` で1回だけ確認してよい。

1. **日付を決める** — メッセージに日付・曜日の言及がなければ「今日」(会話時点の日付)を使う。「先週の土曜」等の相対表現は計算して確定させる。
2. **場所の名前・緯度経度を決める**
   - まず `getItems` で既存の `bug-visits` レコードの `placeName`/`lat`/`lng` を確認し、名前が部分一致・表記ゆれ(送り仮名、「神社」「公園」の有無など)で一致するものがあれば、その `lat`/`lng`/`spotType` をそのまま再利用する(座標を調べ直さない)。
   - 一致する記録が無ければ、質問せずに `WebSearch`/`WebFetch` で場所名から緯度経度を調べる。`spotType` は名前に「神社」があれば神社、「公園」があれば自然公園、それ以外はその他と推定。`placeMemo` に「(チャットから自動登録。緯度経度は自動取得のため要確認)」と書き添える。
3. **生き物と匹数を解釈、「捕まえた」か「見ただけ」かを判定**
   - 文中の生き物名を `creature` enum(セミ/バッタ/カマキリ/カブトムシ/クワガタ/チョウ・蛾/トンボ/カエル/爬虫類/水辺の生きもの/その他の虫/その他)に対応づける。同義語・種名(「ちょうちょ」「モンキチョウ」→チョウ・蛾、「トノサマバッタ」「ショウリョウバッタ」→バッタ、「シオカラトンボ」「アキアカネ」→トンボ、「がまがえる」→カエル、「カナヘビ」「ニホントカゲ」「ヘビ」「ヤモリ」「カメ」等トカゲ・ヘビ・カメの仲間→爬虫類、「ドジョウ」「エビ」「ザリガニ」「カニ」「メダカ」「イモリ」等の水中・水辺の生き物→水辺の生きもの、「ホタル」「テントウムシ」「ダンゴムシ」「カタツムリ」等の上記8カテゴリにも爬虫類・水辺にも当てはまらない虫→その他の虫)も柔軟に解釈し、具体的な種名は `note` に残す。どのカテゴリにも当てはまらない生き物(「ムカデ」等)は `creature: "その他"` にして `note` に実際の名前を書く。匹数の言及がなければ `count: 1` とする。
   - 「捕まえた/ゲットした/つかまえた」と言われたものは `catches`(捕まえた生き物)に、「見た/見つけた/見ただけ/逃げられた」と言われたものは `sightings`(見た生き物・捕まえなかった)に入れる。動詞の言及が無く単に生き物名だけ並んでいる場合は `catches` 扱いにする。
   - `note` に具体的な種名を書く際は、下記「生き物名の表記ゆれ辞書」で正式表記に揃える。
   - 生き物名が下記「総称語は1回だけ質問する」の一覧に載っている曖昧な総称(例:「ザリガニ」)で、メッセージ中に具体的な種名が無い場合は、この時点でレコードをまだ保存せず、`presentForm` で1回だけ確認してから `note` を確定する。該当する総称が複数あれば1つのフォームにまとめて聞く。
4. **天気** — 言及があればそれを最優先で反映。言及が無い場合は、下記の「天気の自動入力」の手順で `jma-weather` コレクションから調べて埋める。それも取れなければ `weather` は省略(スキーマのデフォルト「晴れ」が適用される)。いずれの場合も無理に聞き返さない。
5. **同日・同じ場所の既存レコードがあれば追記、無ければ新規作成**
   - `date` + `placeName`(+ ほぼ同じ `lat`/`lng`)が一致する既存レコードを探す。あれば、その `catches`/`sightings` 配列にそれぞれ新しい行を追加して(既存行は保持したまま)`mode: "merge"` で書き戻す。
   - なければ `id: "<date>-<場所のkebabスラッグ>"` で新規作成(`mode: "create"`)。
6. **確認メッセージ** — 「〇〇神社 9/24: セミ2匹, バッタ1匹を捕まえた(カエルは見ただけ)」のように一言で返す。写真が添付されていれば `photo` にそのパスを書き込み、一言に写真を記録した旨も添える。

この一連の処理は既存の「記録項目」「何をするか」セクションのルールに従いつつ、**質問を増やさず自分で判断して埋める**ことを優先する。

## 天気の自動入力(jma-weather連携)

ワークスペースには気象庁の天気予報スキル `jma-weather` があり、追加のLLM呼び出し無しで全国主要都市+兵庫県(神戸, office `280000`)の天気予報(今日/明日/週間、最大+7日先まで)を保持している。ユーザーが天気を明言しなかった一言登録では、これを使って自動で埋める。

1. 記録する `date` が「今日」〜「+6日先」の範囲内(=予報データがある範囲)かどうか確認する。範囲外(過去の日付、または1週間より先)なら**自動入力は使えない**ので、素直にデフォルト「晴れ」のままにする(気象庁の予報データは実況・過去天気を保持しないため、後から遡って正確な天気を取得することはできない)。
2. 場所の都道府県を判定する(場所を新規登録した際のジオコーディング結果に含まれる都道府県名を使う。既存場所を再利用した場合は `placeMemo` や過去のやり取りから推測)。下記の対応表で `jma-weather` の `office` コードに変換する。表に無い都道府県の場合は自動入力をあきらめ、デフォルトのままにする(無理に一番近い都市で代用しない)。
   | 都道府県 | office |
   |---|---|
   | 兵庫県 | 280000 |
   | 大阪府 | 270000 |
   | 東京都 | 130000 |
   | 神奈川県 | 140000 |
   | 愛知県 | 230000 |
   | 北海道(札幌周辺) | 016000 |
   | 宮城県 | 040000 |
   | 新潟県 | 150000 |
   | 島根県 | 320000 |
   | 香川県 | 370000 |
   | 福岡県 | 400000 |
   | 沖縄県(本島) | 471000 |
3. `manageCollection getItems` で `jma-weather` の `id: "<office>-<date>"` を1件取得し(`fields: ["weather"]` で十分)、その `weather`(JMAの自由文、例:「晴れ 時々 くもり」)を次の優先順で自分たちの enum に変換する: 「雪」を含む→雪、「雨」を含む→雨、「曇」を含む→くもり、「晴」を含む→晴れ、どれにも当てはまらなければ不明。
4. 変換した値を `bug-visits` レコードの `weather` に設定する。取得できなかった場合(レコードが無い等)は何もせずデフォルトのままにする。
5. 新しい都道府県がよく出てくるようになった場合は、`data/skills/jma-weather/scripts/resolve_city.py <市区町村名> --out-dir data/collections/jma-weather/items --write` (曖昧なら `--pick <class20コード>` で確定、`--order` は次の連番)で同様に追加し、`fetch.py --only <office> --out-dir data/collections/jma-weather/items` で即時取得できる。対応表にも追記すること。

## 生き物名の表記ゆれ辞書(noteの正式名統一)

「図鑑」タブは `creature` + `note` の**文字列完全一致**でグルーピングするため、`note` の表記が揺れる(送り仮名・ひらがな/カタカナ・別名)と、本来同じ生き物なのに別カードに分かれてしまう。`catches`/`sightings` の行を書く前に、必ず次の手順で `note` を正式表記に揃える。

1. まず `getItems` で取得済みの既存レコードの `catches[].note`/`sightings[].note` を確認し、今回書こうとしている生き物と同一種と思われる表記(ひらがな⇔カタカナ、送り仮名違いなど)が既にあれば、**その既存表記にそのまま合わせる**(辞書より既存データの実績を優先)。
2. 一致する既存表記が無ければ、下表の正式表記(標準和名のカタカナ表記)を使う。表に無い種は、自分で判断した標準和名のカタカナ表記を書き、次によく出てくるようならこの表に追記する。

| `creature` | 正式表記(note) | よくある表記ゆれ・別名 |
|---|---|---|
| セミ | アブラゼミ / クマゼミ / ミンミンゼミ / ツクツクボウシ / ニイニイゼミ | せみ、あぶらぜみ 等 |
| バッタ | トノサマバッタ / ショウリョウバッタ / オンブバッタ / イナゴ | ばった、とのさまばった、しょうりょうばった 等 |
| カマキリ | オオカマキリ / ハラビロカマキリ / コカマキリ | かまきり、おおかまきり 等 |
| カブトムシ | カブトムシ(オス) / カブトムシ(メス) | かぶとむし 等 |
| クワガタ | ノコギリクワガタ / コクワガタ / ミヤマクワガタ | くわがた、のこぎりくわがた 等 |
| チョウ・蛾 | モンシロチョウ / モンキチョウ / アゲハチョウ / キアゲハ | ちょうちょ、もんきちょう、あげは 等 |
| トンボ | シオカラトンボ / アキアカネ / ハグロトンボ / オニヤンマ / ギンヤンマ | とんぼ、しおからとんぼ、あかとんぼ(→アキアカネ) 等 |
| カエル | アマガエル / ヒキガエル / トノサマガエル / ウシガエル | かえる、がまがえる(→ヒキガエル)、あまがえる 等 |
| 爬虫類 | カナヘビ / ニホントカゲ / ヤモリ / アオダイショウ / クサガメ | とかげ(→ニホントカゲ)、へび、かめ 等 |
| 水辺の生きもの | ドジョウ / エビ / アメリカザリガニ / サワガニ / メダカ / アカハライモリ | ざりがに(→アメリカザリガニ)、いもり(→アカハライモリ) 等 |
| その他の虫 | ホタル / テントウムシ(ナナホシテントウ等) / ダンゴムシ / カタツムリ | ほたる、てんとうむし 等 |
| その他 | ムカデ 等(上記どれにも当てはまらない生き物) | むかで 等 |

この辞書はあくまで目安なので、無理に厳密化して質問を増やさない — 一致しそうな表記が見つからなければ素直に標準和名を書けばよい。

## 総称語は1回だけ質問する(要確認リスト)

「ザリガニ」のように、複数の具体的な種が考えられる**総称**でユーザーが伝えてくることがある。図鑑の精度のために本来の種名で記録したいので、下の一覧に載っている総称が出てきて、かつメッセージ中に具体的な種名が書かれていない場合に限り、レコードを保存する前に **`presentForm` で1回だけ** 尋ねる。それ以外の生き物名では、ワンライン登録の「質問しない」原則どおり、これまでどおり質問しない。

- 対象はこの一覧に載っている語だけ。セミ/バッタ/カマキリ/カブトムシ/クワガタ/チョウ・蛾/トンボ/カエルの主要8カテゴリを総称で言われた場合(例:「トンボ」とだけ言われた等)は、この仕組みの対象外 — 上の表記ゆれ辞書の代表種を使うか `note` を空欄にしてよく、質問しない。
- 1回のメッセージに該当する総称が複数あれば、`presentForm` の質問を1つのフォームにまとめて一度に聞く(生き物ごとに1フィールド)。
- 各質問には必ず「わからない(そのまま記録)」の選択肢を入れる。これが選ばれた場合は総称のまま(例:「ザリガニ」)を `note` に書き、登録は止めない。
- 回答が得られたら、その正式種名を `note` に書き、通常の手順(表記ゆれ辞書での統一含む)に戻ってレコードを保存する。

| 総称 | 候補 | 備考 |
|---|---|---|
| ザリガニ | アメリカザリガニ / ニホンザリガニ / わからない(そのまま記録) | 大半はアメリカザリガニだが念のため確認 |
| ヘビ | アオダイショウ / シマヘビ / ヤマカガシ / わからない(そのまま記録) | 見分けが難しければ「わからない」でよい |
| カメ | クサガメ / ミシシッピアカミミガメ(ミドリガメ) / わからない(そのまま記録) | `creature` は `爬虫類` として登録 |

このリストは今後も伸ばしてよい。「総称のまま記録すると図鑑で紛れやすい」生き物が新しく出てきたら、ここに追記する。

## 記録項目

- `id` — kebab-case のスラッグ(主キー、ファイル名)。例: `2026-09-24-kamisakabe-nishi-koen`(日付-場所スラッグ)
- `date` — お出かけの日付(必須)。カレンダービューの基準日。
- `placeName` — 場所の名前(必須)。例: 「日向神社」「上坂部西公園」
- `spotType` — enum: 神社 / 自然公園 / 公園 / その他(デフォルト「自然公園」)
- `lat` / `lng` — 緯度・経度(必須)。地図タブのピン表示に使う。既存レコードに同じ場所があればその値を再利用し、無ければ調べて埋める。
- `placeMemo` — 場所についてのメモ(アクセス・特徴など、任意)
- `weather` — enum: 晴れ / くもり / 雨 / 雪 / 不明(デフォルト「晴れ」)
- `catches` — 捕まえた生き物のテーブル。1行 = 1種類の生き物。
  - `creature` — enum: セミ / バッタ / カマキリ / カブトムシ / クワガタ / チョウ・蛾 / トンボ / カエル / 爬虫類 / 水辺の生きもの / その他の虫 / その他
  - `count` — 匹数(数値)
  - `note` — メモ(任意。具体的な種名や、大きさ・様子など)
- `sightings` — 見ただけ(捕まえなかった)生き物のテーブル。列構成は `catches` と同じ(`creature`/`count`/`note`)。
- `photo` — 写真(任意)。`[Attached file: ...]` のパスをそのまま書き込む。
- `memo` — 感想・メモ(任意)

## 何をするか

**追加** — お出かけ1回につき1レコード。`manageCollection` putItems (`mode: "create"`)。ワンライン登録の手順に従う。
**更新** — 同じお出かけに後から生き物を追記する場合は `mode: "merge"` で `catches`/`sightings` 配列全体をそれぞれ作り直して送る(部分マージでも配列自体は丸ごと上書きになるので、既存行+新規行をすべて含めること)。
**一覧・カレンダー** — `/collections/bug-visits` で表示。日付ベースでカレンダー表示も可能。
**地図** — 「地図」タブで場所ごとにピンを表示(同じ場所名+座標のレコードは自動でグルーピングして訪問回数を表示)。ポップアップの日付をクリックするとその記録の詳細が開き、「Googleマップで開く」でストリートビュー等も確認できる。
**図鑑** — 「図鑑」タブで、今まで `catches`/`sightings` に出てきた生き物を `creature` カテゴリごと・`note`(具体的な種名。無ければ `creature` 名)ごとにグルーピングして一覧表示する。各カードに捕まえた/見ただけの累計匹数、初めて記録した日付・場所、記録された日付一覧(クリックでその記録を開ける)を表示する。新しい `note` の書き方揺れ(例:「モンキチョウ」と「もんきちょう」)は別種として扱われてしまうので、一言登録で `note` を書く際はできるだけ正式名・カタカナ表記に揃えること。
**集計** — 「今まで何回むしとりに行ったか」「どの生き物が一番多いか」等は `manageCollection` の `getItems`(全件取得して集計)または `queryItems` を使う。
